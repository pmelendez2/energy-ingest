# Home Assistant Energy Usage — Configuration and Meter Status

## Purpose

This development implementation connects Home Assistant to an existing
Energy Ingest API and shows physical-meter status. It does **not** perform
XML import, meter registration, historical Recorder backfill, or create
Energy Dashboard consumption entities.

## Customer experience

1. In Home Assistant, open **Settings → Devices & services**.
2. Select **Add integration**, then select **Energy Usage** once the
   custom integration is installed in a development environment.
3. Enter an API URL reachable from the Home Assistant container and a
   bearer token generated by Energy Ingest.
4. The integration validates credentials and lists registered meters.
5. Each meter receives a usage-status sensor and a resolved-interval
   count sensor. A status of **Needs attention** indicates resolver
   issues; **No usage data** indicates the resolved stream is empty.
6. If credentials are rejected later, the integration supports token
   reauthentication through Home Assistant.

## Development limits

- Use a **development Home Assistant instance**, not the working `piha`
  deployment, until Home Assistant runtime tests pass.
- `127.0.0.1` refers to the Home Assistant container, not a different
  container or the host. Arrange restricted network connectivity; do
  not expose the API publicly.
- Stream responses currently include full interval histories. Polling
  is currently every six hours; bounded historical reads and watermark
  support are required for production-scale synchronization.
- `resolved` and conflict results come from the Rust physical-meter
  resolver. Diagnostic interval counts are not cumulative energy.
- Long-term statistics, unit normalization, backfills, corrections, and
  proper Energy Dashboard entities remain separate implementation work.

## Verification before production

Run Python syntax checks, validate translation JSON, test configuration
and reauthentication against the target Home Assistant version, and run
against a test API with mapped electricity/gas meters and conflict cases.
Keep bearer tokens out of logs and test fixtures.
