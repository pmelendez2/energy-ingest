# Energy Ingest 0.1.10

**Purpose:** Document the Energy Ingest 0.1.10 production release.

**Intended Audience:** Users, contributors, and release maintainers.

## Highlights

- Improved Green Button imports for Net Energy Metering (NEM) data,
  including repeated UsagePoint resources.
- Replaced unmaintained Chrono and Chrono-TZ dependencies with
  maintained `time` and Jiff libraries.
- Improved CI classification, release documentation validation,
  and dependency security.

## Fixes

- Accept equivalent repeated UsagePoint definitions while
  rejecting conflicting resource metadata.
- Preserve separate electricity consumption and export
  observations during imports and reimports.
- Correct dependency security findings by updating SQLx to
  0.9.1, `url` to 2.5.9, and `libsqlite3-sys` to 0.39.1.
- Remove the unmaintained Chrono and Chrono-TZ dependencies.

See issues #41, #42, #43, and #45 and pull request #46.

## Compatibility and upgrade notes

- No intentional database schema changes.
- Existing stored UTC datetime semantics are preserved.
- API timestamp formatting remains unchanged.
- Fingerprints continue to use Unix timestamps.
- Daily natural-gas reporting continues to account for local
  calendar dates and daylight-saving transitions.
- Missing usage readings are never fabricated.
- Solar export and consumption remain distinct; this release
  does not introduce Home Assistant solar-production reporting.

For existing installations, preserve the MariaDB volume,
credentials, original utility XML, and imported readings.
Do not reset the database during an upgrade.

## Verification

The merged implementation passed:

- 223 isolated Rust tests, including MariaDB integration tests.
- Formatting, compilation, and Clippy checks.
- Documentation and architecture-decision conformance.
- Production installer packaging checks.
- Strict RustSec dependency auditing without exceptions.
- GitHub's required isolated CI and Gitleaks checks.

The release-specific production image, runtime, multi-platform,
and publication checks must also pass before publication.

## Known limitations

- Home Assistant solar-production reporting is not implemented.
- Provider-specific support continues to depend on validated
  source metadata and supported import formats.
